# Релиз v1.10.0

## Основные изменения

Релиз **v1.10.0** добавляет глобальную политику фильтрации торрент-трафика с управлением из админ-панели. Это устраняет перерасход трафика на каскаде и снимает типовые DMCA-риски на прямых нодах без внедрения L7/DPI.

---

### 1. Политика фильтрации торрентов (off / soft / strict, TASK-084)

- **Глобальный переключатель режимов** в админ-панели («Настройки» → «Фильтрация торрент-трафика»):
  - `off` — трафик не фильтруется (режим по умолчанию).
  - `soft` — сетевая фильтрация без L7: порты BitTorrent (`6881-6889`, `6969`, `1337`, `2710`, `51413`, TCP+UDP) + блокировка DHT/трекер-доменов через `ipset`.
  - `strict` — зарезервирован под будущий L7/DPI (в UI задизейблен, на API — «не реализовано»).
- **Редактируемый блок-лист доменов** (публичные трекеры + DHT bootstrap) с добавлением/удалением прямо из интерфейса; изменения мгновенно рассылаются на ноды.
- **Точка фильтрации каскада — M0 Ingress**: единый choke point, отбрасывает торрент до входа во внутренний туннель M0→S1/S4, что экономит внутренний трафик. Прямые ноды (S2/SBOX, Hysteria2/Mieru/VLESS) получают те же правила через свой `avari-slave`. Механизм протокол-агностичный.
- **Устойчивость правил**: slave персистит состояние в `/etc/avari-keys/firewall-state.json` и переприменяет при старте (переживает рестарт и ребут); домены ре-резолвятся каждые 15 минут фоновым воркером.

### 2. Архитектура и безопасность

- Новый пакет `internal/firewall` (обёртка `iptables`/`ipset` через инжектируемый executor — полностью тестируется моком).
- Slave-эндпоинты `POST/GET /api/v1/firewall` и `POST /api/v1/firewall/blocklist` под `X-API-Key`; Master-эндпоинты `GET/PUT /api/v1/admin/traffic-policy` и CRUD `/api/v1/admin/torrent-blocklist` (admin-only, с audit-log).
- Новая миграция SQLite v4 (`torrent_blocklist` + сид дефолтного списка); без новых внешних зависимостей, Zero CGo сохранён.
