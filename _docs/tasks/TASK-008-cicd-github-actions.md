# TASK-008: Настройка безопасного CI/CD пайплайна (GitHub Actions -> VPS 192.0.2.20)

## 1. Описание задачи (Specific)
Разработать и внедрить безопасный пайплайн непрерывной интеграции и доставки (CI/CD) на базе GitHub Actions для автоматического обновления Master Backend и Frontend SPA на боевом VPS `192.0.2.20` при изменениях в ветках `main` / `master`.

### Архитектурные требования:
1. **Этап CI**:
   - Автоматический прогон тестов (`go test -v -race ./...`) и статического анализа (`go vet ./...`).
   - Сборка и валидация фронтенда (`npm ci && npm run build`).
   - Кросс-компиляция статических Linux (amd64) Go-бинарников без CGo (`CGO_ENABLED=0`).
2. **Этап CD**:
   - Триггер: `push` в `main`/`master` или ручной запуск (`workflow_dispatch`).
   - Безопасное SSH-подключение через зашифрованные GitHub Secrets (`SSH_PRIVATE_KEY`).
   - Атомарная замена исполняемых файлов через `install` и безопасная синхронизация статики через `rsync --delete`.
   - Автоматический перезапуск сервисов (`systemctl restart avari-master`, `systemctl restart avari-slave`, `systemctl reload caddy`).
   - Health-check верификация успешности старта сервиса после деплоя.
   - Защита от состояния гонки (`concurrency` group).

## 2. Критерии приемки (Measurable)
- [x] Создан конфигурационный файл `.github/workflows/ci-cd.yml`.
- [x] Подготовлена документация `_docs/CICD.md` с пошаговой инструкцией генерации ED25519 ключей и настройки GitHub Secrets.
- [x] Все бэкенд и фронтенд тесты успешно выполняются в изолированном раннере.
- [x] Конфигурация защищена от сбоев при параллельных коммитах и не оставляет недокачанные файлы.

## 3. Достижимость (Achievable)
Используются официальные Actions (`actions/setup-go`, `actions/setup-node`, `actions/upload-artifact`, `actions/download-artifact`) и стандартный OpenSSH протокол.

## 4. Актуальность (Relevant)
Устраняет необходимость ручной загрузки бинарников и статики через scp при каждом обновлении приложения.
