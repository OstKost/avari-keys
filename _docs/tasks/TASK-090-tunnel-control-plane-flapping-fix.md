# TASK-090: Защищенный туннельный Control Plane (Master ↔ Direct Nodes) и устранение ложного флаппинга ТСПУ

## 1. Цели и скоуп
- **Проблема**:
  При обращении Master-бэкенда (на узле M0 в Москве) к Slave API прямого сервера S1 (Германия) по публичному домену (`https://s1.avari.dev` over TCP:443) стандартные TCP SYN-пакеты подвергаются жесткой фильтрации и дропу пограничным узлом FiordNet/ТСПУ (`62.140.245.33`).
  Это приводило к постоянному флаппингу статуса сервера в веб-интерфейсе (`Node DOWN` ↔ `Node RECOVERED`), ложным ночным оповещениям в Telegram и рискам сбоев при создании клиентских ключей из-за таймаутов (15 секунд).
  При этом сам сервер S1 и AmneziaWG-туннели работали без единого сбоя.
- **Решение**:
  1. Перевод служебного канала управления (Control Plane) между Master (M0) и нодой S1 в защищенный AmneziaWG-туннель (`172.16.61.9` ↔ `172.16.61.1:8081`).
  2. Открытие порта Slave API (`8081`) в UFW на S1 исключительно для интерфейса AmneziaWG (`awg0`).
  3. Обновление `api_url` в базе данных Master (`nodes` table) на туннельный адрес `http://172.16.61.1:8081`.
  4. Сохранение полной независимости публичного мониторинга (`netprobe`), который продолжает опрашивать `s1.avari.dev` снаружи для матрицы доступности сети.
  5. Комплексное тестирование всех операций (HealthCheck, сбор статистики телеметрии, выпуск тестового ключа, сетевой мониторинг).

## 2. Затронутые модули и компоненты
- **Инфраструктура и сеть**:
  - Сервер S1: правило UFW `allow in on awg0 to any port 8081 proto tcp`.
  - Сервер M0: `nodes.api_url = 'http://172.16.61.1:8081'` для узла #4.
- **Документация и архитектура**:
  - `_docs/TASKS.md` (обновление канбан-доски).
  - `_docs/architecture/INDEX.md` / `BACKEND_STRUCTURE.md` (фиксация изолированного туннельного Control Plane).
  - `_docs/RELEASE-v1.12.0.md` (описание релиза v1.12.0).
