# TASK-076 — Перенос веб-интерфейса Telegram Mini App

## Цель

Проверить доступность панели и развернуть текущий веб-интерфейс Mini App на зарубежном узле S1 (Германия).

## План

1. Скопировать действующую production-сборку фронтенда на S1 и настроить маршрут Mini App и статические файлы в Caddy.
2. Передавать запросы Master API на существующий Master по HTTPS. Маршруты Slave API направлять на локальный Slave. SQLite и токен бота располагаются на Master. Контракты API, DTO, реальные и mock-клиенты сохраняются.
3. Проверить TLS, загрузку страницы и ресурсов, отказ API при пустом Telegram `initData` и ответ существующего Slave API.
4. Обновить URL Mini App в настройках бота. Для отката восстановить предыдущий URL и при необходимости предыдущую конфигурацию Caddy.

## Проверка

- [x] Страница Mini App и ресурсы доступны на S1.
- [x] Master API через S1 отвечает, пустой `initData` отклоняется.
- [x] Существующая панель и маршрут Slave доступны.
- [x] Новый URL сохранён в настройках бота для `/app`. Проверено чтением из БД и по коду выбора URL.
- [x] Подключён Telegram WebApp SDK перед основным модулем на S1 и во входном HTML фронтенда. Сборка `npm run build` прошла.
- [ ] Глобальная кнопка меню Telegram. Bot API подтвердил запись, но при повторном чтении вернул старый URL.
- [ ] Вход с привязанного аккаунта из клиента Telegram.

## Эксплуатация

Сборка на S1 хранится в `/var/www/avari-miniapp-task076`. Текущий CI обновляет фронтенд на Master, поэтому для S1 требуется отдельно синхронизировать проверенную сборку и её ресурсы после релиза. Резервная конфигурация Caddy на S1 находится в `/etc/caddy/Caddyfile.task076-backup`. Для отката сначала вернуть прежний URL бота, затем при необходимости восстановить конфигурацию Caddy и перезагрузить её.

Панель ответила HTTP 200 из доступных точек проверки. Сбой из сети пользователя не воспроизведён.
