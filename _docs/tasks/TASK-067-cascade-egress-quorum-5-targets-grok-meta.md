**Ветка**: `feature/TASK-067-cascade-egress-quorum`

## 1. Цели и скоуп

1. **Добавление сервисов Grok и Meta**:
   - Расширить список целевых проверок Egress-шлюзов каскадных нод двумя популярными сервисами, заблокированными/ограниченными в РФ:
     - **Grok AI** (`https://grok.com`, настраивается через `AVARI_PROBE_GROK_URL`).
     - **Meta / Instagram** (`https://www.instagram.com`, настраивается через `AVARI_PROBE_META_URL`).
   - Итоговый пул проверок состоит из 5 ключевых направлений:
     1. **`api.ipify.org`** (IPv4-связность и строгое совпадение с внешним эндпоинтом ноды).
     2. **Telegram** (`api.telegram.org` — проверка прямой маршрутизации подсетей Telegram).
     3. **ChatGPT** (`chatgpt.com` — проверка отсутствия блокировки Cloudflare 403 / IP reputation).
     4. **Grok** (`grok.com` — доступность AI-сервиса xAI).
     5. **Meta** (`www.instagram.com` — доступность инфраструктуры Meta).

2. **Кворум успешности (3 из 5)**:
   - Направление считается доступным (`available: true`), если успешно завершились **как минимум 3 из 5** проверок ($\ge 3/5$).
   - Это защищает от ложных переключений и флаппинга при локальных технических сбоях или регламентных работах на стороне одного из внешних сервисов (например, кратковременный сбой у OpenAI или Meta).
   - Если успешных проверок менее 3 ($< 3/5$), статус направления помечается как недоступный (`available: false`), а в поле `reason` формируется подробный отчет о сбоях (например: `успешно 2/5 проверок (сбои: chatgpt заблокирован (HTTP 403); grok недоступен: timeout; meta недоступен: timeout)`).

3. **Параллельное выполнение**:
   - Все 5 проверок для каждого интерфейса запускаются параллельно в горутинах, что сохраняет общее время проверки в пределах ~1 секунды.

- `apps/backend/internal/egress/probe.go` — параллельный запуск 5 проверок, алгоритм подсчета кворума (3 из 5), формирование детализированного `reason`.
- `apps/backend/internal/egress/egress_test.go` — модульные тесты:

  - 0 из 5 успешно -> `available: false`.
