# Телеметрия трафика, месячный учет и биллинг

## 1. Телеметрия трафика (Curve25519 & Delta Engine)

### 1.1 Сопоставление ключей (Curve25519 Derivation)
Команда `awg show <interface> transfer` выдает статистику по `PublicKey` пиров:
```text
<PublicKey>    <rx_bytes>    <tx_bytes>
```
Для сопоставления со старыми конфигурациями, где в базе был известен только `PrivateKey`, используется криптографическая деривация публичного ключа на эллиптической кривой Curve25519 (`golang.org/x/crypto/curve25519`).

### 1.2 Инкрементальный Delta Engine
Счетчики трафика ОС WireGuard обнуляются при перезагрузке сервера или перезапуске демона (`systemctl restart`).
Чтобы предотвратить потерю накопленной статистики, в Master реализован **Delta Engine**:
1. При каждом опросе фиксируется текущее значение байт интерфейса.
2. Вычисляется дельта: $\Delta = \text{Current} - \text{Previous}$.
3. Если $\text{Current} < \text{Previous}$ (произошел сброс счетчика ОС), дельта принимается равной $\text{Current}$.
4. Дельта атомарно прибавляется к посуточной таблице `peer_traffic_daily` и `node_traffic_daily` в SQLite:
   ```sql
   INSERT INTO peer_traffic_daily (date, client_config_id, rx_bytes, tx_bytes)
   VALUES (?, ?, ?, ?)
   ON CONFLICT(date, client_config_id) DO UPDATE SET
       rx_bytes = rx_bytes + excluded.rx_bytes,
       tx_bytes = tx_bytes + excluded.tx_bytes;
   ```

## 2. Учет трафика за календарный месяц (TASK-082)

Для обеспечения стабильности каналов и контроля Fair Use (предотвращения перегрузки серверов отдельными пользователями) реализован помесячный учет трафика:

### Ключевые методы Storage:
- **`GetUserMonthTraffic(ctx, userID, monthStr)`**:
  - Суммирует байты приема и передачи по всем ключам пользователя за указанный месяц (`YYYY-MM`).
  - Возвращает структуру `models.UserMonthTraffic` (`RxBytes`, `TxBytes`, `TotalBytes`, `Formatted`).
- **`GetUsersMonthTrafficMap(ctx, monthStr)`**:
  - Пакетная агрегация трафика по всем пользователям за один SQL-запрос (`GROUP BY user_id`), ликвидирующая проблему N+1 запросов при открытии списка пользователей админом.

### Отображение в интерфейсах:
- **Личный кабинет (`ClientKeysView.tsx`)**: баннер общего трафика за текущий месяц над списком ключей.
- **Таблица CRM пользователей (`AdminUsers.tsx`)**: колонка «Трафик за месяц» с цветовой индикацией объемов.
- **Telegram Mini App (`TelegramMiniApp.tsx`)**: сводка потребления трафика на главном экране профиля.

## 3. Кооперативный биллинг (Кооперативные взносы)

Биллинговая система проекта основана на механизме ежемесячных членских взносов для совместного покрытия расходов на инфраструктуру (VPS в РФ и Европе).

### 3.1 Расчет суммы взноса
- **Базовый взнос**: 300 ₽ за 30 дней.
- **Плата за дополнительные ключи**: +50 ₽ в месяц за каждый активный ключ сверх базовой квоты.
- Формула рассчитывается динамически в `handleGetBillingStatus` (`apps/backend/internal/master/handlers_billing.go`).

### 3.2 Жизненный цикл оплаты
1. Раз в 30 дней пользователю выставляется напоминание об оплате членского взноса.
2. **Отсрочка (Snooze)**: Пользователь может нажать кнопку «Отложить на 7 дней» (`POST /api/v1/billing/snooze`). Запись сохраняется в `app_settings` (`billing_snooze_until:<userID>`).
3. **Подтверждение оплаты**: При получении взноса администратор подтверждает оплату через Mission Control (`POST /api/v1/billing/pay`). В таблице `billing_records` создается подтвержденная запись, а таймер взноса сбрасывается на следующие 30 дней.
4. **Реквизиты**: Администратор может обновлять текст реквизитов (номера карт, СБП, кошельки) через веб-интерфейс (`PUT /api/v1/admin/billing/requisites`).
