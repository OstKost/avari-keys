# Релиз v1.8.0

## Основные изменения

Релиз **v1.8.0** добавляет полноценную поддержку четвёртого протокола обхода блокировок — **VLESS+Reality** на прямых зарубежных нодах (Direct Nodes). Архитектура обеспечивает полную изоляцию секретов на стороне нод (Zero-Secret Leaks на Master), мгновенный отзыв доступа при компрометации, генерацию `vless://` URI и JSON-конфигураций для клиента AvariGate, синхронизированный автономный режим `dev:mock`, а также закрепляет архитектурный инвариант **Upstream Core Neutrality & Brand Neutrality** (Инвариант 11 в AGENTS.md).

---

### 1. Протокол VLESS+Reality на прямых серверах (Direct Nodes)
- **Интеграция Xray-core на Slave-агентах**:
  - Управление выделенной изолированной службой `avari-vless.service` на базе официального Xray-core.
  - Реализация безопасного хранения конфигурации с правами `0600` и запуском через `systemd LoadCredential` без root-привилегий (`DynamicUser=yes`, `CAP_NET_BIND_SERVICE`).
  - Поддержка параметров безопасности REALITY (`security=reality`, flow `xtls-rprx-vision`, SNI-маскировка, fingerprint `chrome`, генерация `shortIds` и X25519-ключей).
- **Изоляция приватных ключей и UUID (Zero-Secret Master DB)**:
  - Приватные ключи REALITY и клиентские UUID генерируются и сохраняются исключительно на стороне соответствующей ноды.
  - Master сохраняет в базе данных SQLite только публичные метаданные (`client_name`, `device_name`, `node_id`, `user_id`, `protocol = 'vless'`).
- **Мгновенный отзыв и целостность**:
  - Удаление ключа производит атомарное удаление клиента из конфигурации Xray на Slave с мягким перезапуском службы.
  - При сбое обновления Xray отзыв ключа откатывается, гарантируя согласованность состояния.

### 2. Защита базы данных SQLite и транзакционная безопасность
- **SQL-триггеры валидации и защиты связей**:
  - `validate_vless_owner`: Запрещает создание VLESS-ключей на неактивных нодах, каскадных нодах (поддерживаются только `direct`), а также пользователями без PRO-подписки на резервных нодах.
  - `guard_vless_user`: Предотвращает удаление пользователя администратором до тех пор, пока не будут корректно отозваны все активные VLESS-ключи на физических нодах.
  - `guard_vless_node`: Предотвращает удаление ноды до завершения отзыва всех привязанных к ней VLESS-ключей.
- **Поддержка миграции схемы БД**:
  - Добавлена колонка `has_vless INTEGER NOT NULL DEFAULT 0` в таблицу `nodes`.

### 3. Веб-интерфейс и Telegram Mini App
- **Поддержка VLESS в окне создания ключей (`CreateKeyModal.tsx`)**:
  - Селектор протокола с иконкой и описанием возможностей VLESS+Reality.
  - Автоматическая валидация доступности протокола на выбранном сервере.
- **Отображение и экспорт ключа (`KeyModal.tsx`)**:
  - Экспорт ссылки подключения `vless://...`.
  - Генерация QR-кода для мгновенного импорта в мобильные клиенты (Hiddify, NekoBox, Sing-box).
  - Выгрузка готового JSON-профиля, полностью совместимого с настольным клиентом AvariGate Desktop.
- **Интеграция в Telegram Mini App (`TelegramMiniApp.tsx`)**:
  - Выбор протокола VLESS+Reality при создании ключа через Mini App.
  - Отображение статуса протокола, бейджей безопасности и скачивание `.json` профиля.
  - Подключение официального Telegram WebApp SDK в `index.html`.
- **Управление нодами для администратора (`AdminNodes.tsx`)**:
  - Чекбокс включения/отключения поддержки VLESS+Reality на прямых серверах.
  - Отображение статуса готовности `vless_available` в диагностике ноды (`ServerDetailPage.tsx`).
- **Синхронизация Mock Mode (`mockClient.ts`)**:
  - Полная поддержка эмуляции выдачи, валидации и отзыва VLESS-ключей в режиме `npm run dev:mock`.

### 4. Архитектурный инвариант Brand Neutrality (Инвариант 11)
- В `AGENTS.md` закреплены обязательные правила изоляции upstream-ядра экосистемы `avari-*` от любых сторонних коммерческих названий, логотипов и партнерских интеграций.
- Все встроенные стили и компоненты именуются строго нейтрально, а downstream-дистрибуции изолируются в отдельные downstream-репозитории.
