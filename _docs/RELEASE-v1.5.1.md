# Релиз v1.5.1

## Основные изменения

### 1. Разделение проверок TCP / UDP в сетевом мониторинге (TASK-069)
- **Точная классификация сбоев в сетевых зондах (`netprobe`)**:
  - Диагностика сетевых зондов M0/S0 теперь четко различает характер недоступности:
    - **Избирательная блокировка TCP (ТСПУ)**: если ICMP Ping успешен, а TCP-порт веб-панели недоступен, выдается точное заключение:
      `"TCP-порт (HTTP/S) заблокирован ТСПУ/провайдером. Замаскированный UDP-трафик VPN (AmneziaWG/Hysteria2) работает независимо"`.
      Это исключает ложную панику при блокировках веб-портов РКН/ТСПУ, когда сами VPN-туннели продолжают функционировать штатно.
    - **Несовпадение DNS**: фиксируется статус `"DNS не содержит настроенный публичный IP узла"`.
    - **Полный отказ связи**: фиксируется статус `"Узел полностью недоступен по публичной сети (ICMP и TCP не отвечают)"`.
- **Структурированная диагностика по протокольным уровням в UI**:
  - В карточке сервера ([`ServerDetailPage.tsx`](file:///Volumes/KingstonM2/Projects/avari-keys-mvp/apps/frontend/src/components/ServerDetailPage.tsx)) сетевые проверки сгруппированы в три прозрачных слоя:
    1. **🌐 Публичная доступность**: DNS резолв, ICMP Ping, TCP веб-порт с наглядным предупреждающим баннером при избирательной блокировке TCP;
    2. **🛡️ VPN-протоколы и туннелирование (UDP)**: статусы сервисов AmneziaWG (UDP 443) и Hysteria 2 (UDP 8443), количество активных пиров, свежесть последних хэндшейков и объем переданного трафика;
    3. **⚙️ Служебный контур (Master ↔ Slave API)**: прямой отклик API управления и диагностика внутренней связи между нодами кластера.
  - В общем списке серверов ([`AdminNodes.tsx`](file:///Volumes/KingstonM2/Projects/avari-keys-mvp/apps/frontend/src/components/AdminNodes.tsx)) проверки зондов дополнены протокольными тегами (`ICMP`, `TCP`, `DNS`) с цветовой индикацией состояния.
- **Устойчивость маршрутизации Master (M0 -> S3, S4)**:
  - В конфигурацию AmneziaWG-туннеля `awg0` на M0 добавлены маршруты до сингапурского узла S3 (`192.0.2.23/32`) и узла VDSina S4 (`192.0.2.24/32`).
  - Master Backend сохраняет стабильный доступ к Slave API всех зарубежных нод для выпуска клиентских ключей и сбора телеметрии независимо от блокировок веб-трафика провайдерами РФ.
- **Синхронизация Mock Mode**:
  - Данные тестовых сетевых проверок и протоколов полностью синхронизированы в [`mockClient.ts`](file:///Volumes/KingstonM2/Projects/avari-keys-mvp/apps/frontend/src/api/mockClient.ts) для автономного режима разработки (`npm run dev:mock`).
