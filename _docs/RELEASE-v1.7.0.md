# Релиз v1.7.0

## Основные изменения

Релиз **v1.7.0** представляет комплексное обновление надежности каскадной маршрутизации (Double-Hop Cascade), защиту сетевых зондов от DNS-отравления, обнаружение зависших сессий WireGuard, интеграцию пула из 4 независимых IP-провайдеров, а также расширенные инструменты ручной диагностики в Web-интерфейсе и Telegram Mini App.

---

### 1. Отказоустойчивый пул из 4 IP-провайдеров (Multi-Provider IP Fallback)
- **Устранение единой точки отказа**:
  - Ранее сетевой зонд опирался исключительно на `https://api.ipify.org`. Anycast-сеть Lumen (`8.6.112.0`/`8.47.69.0`), обслуживающая ipify, имеет 100% потерю пакетов у ряда зарубежных провайдеров (например, ihor-hosting на S2 в Финляндии), из-за чего полностью исправный узел отбраковывался как нерабочий.
  - Внедрен последовательный пул из **4 независимых IP-провайдеров**:
    1. `https://api.ipify.org`
    2. `https://icanhazip.com`
    3. `https://ipinfo.io/ip`
    4. `https://api.myip.com`
- **Универсальный парсинг тела ответа (`ParseIPv4FromBody`)**:
  - Реализован интеллектуальный парсер с поддержкой чистого текста, JSON формата (`api.myip.com` возвращает `{"ip":"...","country":"..."}`) и регулярных выражений для извлечения IPv4.

### 2. Защита от цензуры и отравления DNS через DNS over HTTPS (DoH)
- **Изоляция проверок от DNS-фильтрации в РФ**:
  - При выполнении сетевых зондов `curl` через туннели `awgX` сокет привязывался к интерфейсу, однако системный резолвер libc обращался к локальным DNS РФ хоста Ingress (M0), что приводило к сбоям `instagram.com` (`exit status 6`) и подмене IP для `chatgpt.com` / `grok.com`.
  - Зонд теперь использует `--doh-url https://dns.google/dns-query` (с плавным fallback при отсутствии поддержки curl), направляя шифрованные DNS-запросы непосредственно через туннель Egress к зарубежным DNS-серверам Google. Все 5 из 5 проверок (IP, Telegram, ChatGPT, Grok, Meta) теперь стабильно и точно подтверждают доступность шлюзов.

### 3. Детектирование и авто-сброс зависших сессий WireGuard (Frozen Sessions)
- **Сбор телеметрии из дампа интерфейса (`awg show <iface> dump`)**:
  - Вычисляется точный возраст последнего рукопожатия (`HandshakeAgeSec`) и объем полученных данных (`transfer_rx`).
  - Сессия помечается как зависшая (`IsFrozen = true`), если рукопожатие не обновлялось более 180 секунд либо получено 0 байт при наличии отправленного трафика (потеря NAT-сессии у хостера).
- **Готовые рекомендации по восстановлению**:
  - Система формирует четкую сервисную команду для администратора: `systemctl restart awg-quick@<iface>`.
- **Автоматический сброс перед переключением каскада**:
  - При ручном или автоматическом переключении на шлюз с зависшей сессией `manager.go` автоматически выполняет `awg-quick down` + `awg-quick up` перед перепривязкой таблицы маршрутизации, предотвращая сбои трафика.

### 4. Оповещения в Telegram-боте (`NotifyCascadeEgressFrozen`)
- **Уведомления администраторам сети**:
  - При обнаружении фоновым мониторингом зависшей сессии шлюза бот отправляет оповещение с указанием узла каскада, интерфейса, возраста последнего рукопожатия и готовой команды для перезапуска.
  - Встроен 1-часовой механизм дебаунсинга (дедупликации) для предотвращения спама в чатах.

### 5. Ручная проверка шлюзов в Web-интерфейсе и Telegram Mini App
- **Страница сервера (`ServerDetailPage.tsx`)**:
  - Добавлена кнопка **«Проверить шлюзы»** с анимированным спиннером, запускающая немедленный опрос доступности всех шлюзов выхода.
  - Карточки направлений отображают возраст хэндшейка, статус зависания (`❄️ Завис`) и блок с рекомендацией по сбросу службы.
- **Модальное окно переключения (`AdminNodes.tsx`)**:
  - В заголовок модального окна встроена кнопка «Проверить» для оперативной экспресс-проверки направлений прямо перед выбором нового шлюза.
- **Telegram Mini App (`TelegramMiniApp.tsx`)**:
  - Вкладка «Каскад» обновлена под новую архитектуру: добавлена кнопка экспресс-проверки, микро-бейджи 5 проверок, индикация хэндшейка, плашка `❄️ ЗАВИС` и компактный блок рекомендаций.
- **Синхронизация Mock Mode (`mockClient.ts`)**:
  - Все мок-структуры и эндпоинты в `dev:mock` полностью обновлены с поддержкой новых параметров.
