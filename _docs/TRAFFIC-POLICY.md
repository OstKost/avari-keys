# Фильтрация торрент-трафика (off / soft / strict)

Глобальная политика фильтрации торрент-трафика на выходных нодах. Управляется в админ-панели: **Настройки → «Фильтрация торрент-трафика»**.

## Режимы

| Режим | Поведение |
|---|---|
| `off` | Трафик не фильтруется (пассивный режим по умолчанию). |
| `soft` | Сетевая фильтрация без L7: порты BitTorrent + блокировка DHT/трекер-доменов через `ipset`. |
| `strict` | Зарезервирован (L7/DPI). В UI задизейблен, на API возвращает ошибку «не реализовано». |

## Как работает `soft`

На каждой ноде создаётся пользовательская цепочка iptables `AVARI_TORRENT` (jump из `FORWARD` и `OUTPUT`) с правилами:

- **Порты** (TCP+UDP): `6881-6889`, `6969`, `1337`, `2710`, `51413`.
- **`ipset avari_torrent_trackers`** — домены блок-листа (публичные трекеры + DHT bootstrap) резолвятся в IP и матчатся по `dst`.

Точка фильтрации каскада — **M0 Ingress** (единый choke point, экономит внутренний трафик M0→S1/S4). Прямые ноды (S2/SBOX, Hysteria2/Mieru/VLESS) получают те же правила через свой `avari-slave`. Правила протокол-агностичны: AWG — `FORWARD`, proxy-демоны — `OUTPUT`.

## Включение

1. В админ-панели откройте **Настройки** → **Фильтрация торрент-трафика**.
2. Выберите режим `soft`. Master сохранит политику и разошлёт её на все активные ноды (`applied_nodes`/`failed_nodes` в ответе).
3. Блок-лист редактируется там же (добавить/удалить домен); изменения сразу рассылаются на ноды.

## Проверка на ноде

```sh
# Цепочка и правила soft
iptables -S AVARI_TORRENT

# Разрешённые IP доменов блок-листа
ipset list avari_torrent_trackers

# Сохранённое состояние (переживает рестарт slave/ребут ноды)
cat /etc/avari-keys/firewall-state.json
```

Резолв доменов в IP повторяется каждые **15 минут** фоновым воркером slave, поэтому смена IP трекеров подхватывается автоматически.

## Откат

Выберите `off` в админке — Master снимет правила на всех нодах (удаляются цепочка, ipset и state-файл). Локально можно снять вручную:

```sh
iptables -D FORWARD -j AVARI_TORRENT 2>/dev/null
iptables -D OUTPUT -j AVARI_TORRENT 2>/dev/null
iptables -F AVARI_TORRENT 2>/dev/null
iptables -X AVARI_TORRENT 2>/dev/null
ipset destroy avari_torrent_trackers 2>/dev/null
```

## Устойчивость и деплой

- Правила переживают рестарт slave и ребут ноды: slave персистит состояние в `FIREWALL_STATE_PATH` (по умолчанию `/etc/avari-keys/firewall-state.json`) и переприменяет при старте.
- В `deploy/systemd/avari-slave.service` задан `ExecStartPre=/bin/mkdir -p /etc/avari-keys` и `Environment=FIREWALL_STATE_PATH=...`.
- **Egress-ноды без `avari-slave`** (чистые WireGuard-эндпоинты S1/S4) в рассылку не попадают — при необходимости ставьте правила скриптом вручную. Штатная точка фильтрации каскада — M0, поэтому это не обязательно.

## Ограничения `soft`

- Это не L7: зашифрованный peer-wire (MSE/PE) на случайном порту по содержимому не отличить. `soft` душит peer-discovery (порты + DHT + трекеры), что устраняет основную массу бытового торрент-трафика, но не гарантирует 100% блокировку.
- Резолв идёт только по IPv4 (`hash:ip`). IPv6-пиры в текущей версии не покрываются.
- Полная гарантированная блокировка — только egress-lockdown (whitelist портов), ломает игры/звонки, включать точечно.
