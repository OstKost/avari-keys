# Релиз v1.5.0

## Основные изменения

### 1. Нативный Go-контроллер Egress каскада (TASK-066)
- **Полная замена Python-скрипта на нативный Go**:
  - Модуль управления маршрутизацией каскада переписан на чистый Go в пакете `apps/backend/internal/egress/` (`manager.go`, `probe.go`, `routes.go`, `config.go`, `executor.go`).
  - Устранена зависимость от Python (`python3`, `urllib`) и внешней утилиты `avari-egress.py` на входных каскадных узлах M0.
  - Демон `avari-slave` получил встроенные CLI-подкоманды:
    - `avari-slave egress status` — вывод активного интерфейса, списка шлюзов и статусов доступности в формате JSON;
    - `avari-slave egress switch <iface>` — атомарное переключение маршрутов каскада с созданием транзакционного файла восстановления;
    - `avari-slave egress recover` — автоматический откат к предыдущему шлюзу при сбое переключения.
- **Интеграция с демоном и автоматизация путей**:
  - В скрипты инсталляции и деплоя (`scripts/install_egress.sh`, `scripts/deploy_slave_nodes.sh`) добавлено автоматическое создание симлинка `/usr/local/libexec/avari-egress -> /usr/local/bin/avari-slave`.
- **Оптимизация периодичности HealthCheck**:
  - Базовый интервал автоматической проверки здоровья нод и каскадов `HEALTHCHECK_INTERVAL_SEC` увеличен с 60 секунд до **3 минут (180 сек)**, что существенно снижает паразитную нагрузку на каналы и API целевых сервисов.

### 2. Мультипроверка Egress-шлюзов с кворумом 3 из 5 (TASK-067)
- **Комплексный мониторинг через 5 независимых зондов**:
  - Для объективной оценки доступности зарубежного сегмента интернета без ложных блокировок со стороны CDN внедрена проверка 5 целевых адресов:
    1. **IPify** (`https://api.ipify.org` / `AVARI_PROBE_IP_URL`) — верификация внешнего IP и сверка с ожидаемым адресом ноды;
    2. **Telegram API** (`https://api.telegram.org` / `AVARI_PROBE_TELEGRAM_URL`) — проверка доступности мессенджера и инфраструктуры Telegram;
    3. **ChatGPT** (`https://chatgpt.com` / `AVARI_PROBE_CHATGPT_URL`) — проверка доступа к сервисам генеративного ИИ OpenAI;
    4. **Grok** (`https://grok.com` / `AVARI_PROBE_GROK_URL`) — проверка доступа к сервисам xAI;
    5. **Meta / Instagram** (`https://www.instagram.com` / `AVARI_PROBE_META_URL`) — проверка обхода блокировок сервисов Meta.
- **Параллельное исполнение и кворум**:
  - Все 5 проверок выполняются параллельно через горутины с индивидуальным таймаутом по 7 секунд, общее время зондирования составляет всего ~0.5–1.2 секунды.
  - **Кворум успешности**: шлюз признается работоспособным при успешном прохождении **минимум 3 из 5 проверок**.

### 3. Hardening Egress-каскада: Fast Retry и IP Safety Gate (TASK-068)
- **Fast Confirmation Retry (15 секунд)**:
  - При обнаружении сбоя активного шлюза каскада фоновый мониторинг Master не ожидает полные 3 минуты следующего цикла, а немедленно планирует контрольную перепроверку через **15 секунд**.
  - Это сокращает время реакции на аварии шлюза до считанных секунд, сохраняя защиту от ложных переключений при единичных сетевых флапах.
- **IP Safety Gate (Защита от утечки трафика в РФ)**:
  - Сверка исходящего внешнего IP-адреса с целевым эндпоинтом ноды выхода (`target.Endpoint`) является строгим обязательным условием.
  - Если IP-адрес не совпадает (сигнализируя об утечке трафика в локальный интерфейс РФ), шлюз немедленно бракуется даже при доступности остальных тестовых ресурсов.
- **Детализация проверок в UI и синхронизация Mock**:
  - В модальное окно переключения шлюза (`AdminNodes.tsx`) и на детальную страницу сервера (`ServerDetailPage.tsx`) добавлены аккуратные микро-бейджи со статусами каждого из 5 зондов (`IP`, `TG`, `GPT`, `GRK`, `META`) и итоговым счетчиком (`5/5 OK`, `4/5 PASS`, `FAIL`).
  - Полная поддержка новых полей (`passed_checks`, `total_checks`, `checks`) в `mockClient.ts` для автономного режима разработки (`npm run dev:mock`).

### 4. Разделение проверок TCP / UDP в сетевом мониторинге и аудит протоколов VPN (TASK-069)
- **Точная классификация сбоев в `netprobe`**:
  - Диагностика сетевых зондов теперь четко дифференцирует причины недоступности:
    - Сбой только TCP веб-порта при успешном ICMP Ping идентифицируется как блокировка ТСПУ/провайдера (`"TCP-порт (HTTP/S) заблокирован ТСПУ/провайдером. Замаскированный UDP-трафик VPN (AmneziaWG/Hysteria2) работает независимо"`).
    - Несовпадение DNS с настроенным публичным адресом фиксируется как `"DNS не содержит настроенный публичный IP узла"`.
    - Полная потеря связи помечается как `"Узел полностью недоступен по публичной сети (ICMP и TCP не отвечают)"`.
- **Структурированная диагностика по протокольным уровням в UI**:
  - В карточке сервера (`ServerDetailPage.tsx`) зонды сгруппированы на логические слои:
    - **🌐 Публичная доступность** (DNS, ICMP Ping, TCP веб-порт) с предупреждающим баннером при избирательной блокировке веб-портов ТСПУ.
    - **🛡️ VPN-протоколы и туннелирование (UDP)** (AmneziaWG UDP 443, Hysteria 2 UDP 8443, активность пиров, свежесть хэндшейков).
    - **⚙️ Служебный контур (Master ↔ Slave API)** (прямой отклик API управления).
  - В общем списке серверов (`AdminNodes.tsx`) в выпадающем списке зондов добавлены протокольные теги (`ICMP`, `TCP`, `DNS`) с цветовой индикацией.
- **Устойчивость маршрутизации Master (M0 -> S3, S4)**:
  - Добавление маршрутов для узлов S3 Сингапур и S4 VDSina в AmneziaWG-туннель `awg0` на M0 обеспечивает надежное управление всеми узлами кластера даже при внешних сетевых аномалиях.
