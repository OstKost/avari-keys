# Релиз v1.12.0

## Защищенный туннельный Control Plane (Master ↔ Direct Nodes), устранение ложного флаппинга ТСПУ и ультра-лаконичные алерты шлюзов каскада

Релиз **v1.12.0** устраняет ключевую эксплуатационную уязвимость оркестрации прямых нод ([TASK-090](./tasks/TASK-090-tunnel-control-plane-flapping-fix.md)), при которой запросы Master-бэкенда (из РФ) к Slave API зарубежных серверов через открытый интернет (TCP:443) подвергались фильтрации и дропу пограничными узлами ТСПУ/DPI (FiordNet `62.140.245.33`), вызывая ложные срабатывания `Node DOWN` ↔ `Node RECOVERED` и риски сбоев при создании клиентских VPN-ключей.

Также в релиз вошла оптимизация шаблонов уведомлений Telegram-бота для зависших и восстановившихся шлюзов выхода каскада (перевод на ультра-лаконичный двухстрочный формат).

### 1. Защищенный туннельный Control Plane (Master ↔ Slave)

- **Проблема**:
  При обращении Master-бэкенда к прямому серверу S1 (Германия) по публичному домену `https://s1.avari.dev` (TCP порт 443) сетевые пакеты глушились ТСПУ на пограничном транзитном узле, вызывая систематические таймауты (15 секунд). При этом сам сервер S1 и AmneziaWG-туннели работали без единого сбоя.
- **Архитектурное решение**:
  - Канал управления (Control Plane) между Master (M0) и нодой S1 переведён в защищенный AmneziaWG-туннель (`172.16.61.9` ↔ `172.16.61.1:8081`).
  - Порт Slave API (`8081`) на S1 открыт в UFW строго для туннельного интерфейса `awg0` и полностью изолирован от внешнего интернета.
  - В SQLite Master адрес `api_url` ноды #4 переключен на внутренний адрес туннеля (`http://172.16.61.1:8081`).
  - Трафик управления теперь маскируется DPI-заголовками AmneziaWG (`Jc`, `S1`, `S2`, `H1-H4`), исключая блокировку ТСПУ.
  - Время отклика HealthCheck и сбора телеметрии снизилось с нестабильных 15000+ мс до мгновенных 20–40 мс с 0% потерь.

### 2. Чистое разделение Control Plane и Public Network Probes

- **Control Plane**: гарантирует надежность административных операций (создание, отзыв ключей, сбор статистики, перезапуск) по защищенному внутреннему туннелю.
- **Public Network Probes**: механизм `netprobe` продолжает независимо мониторить публичную доступность `s1.avari.dev` снаружи для сетевой матрицы и диагностики доступности для клиентов из РФ без влияния на статус жизнедеятельности ноды.

### 3. Ультра-лаконичные оповещения Telegram о шлюзах каскада

Шаблоны оповещений о зависших и восстановившихся сессиях WireGuard/AmneziaWG-шлюзов выхода каскада сокращены до компактных 2 строк без псевдографики и избыточных текстов рекомендаций:

- **Зависание сессии шлюза**:
  ```html
  ❄️ <b>[Avari] Зависла сессия шлюза [РЕЗЕРВ]</b>
  Каскад: <b>Общий каскад S0</b> (#1) → <b>S4 — VDSina</b> (<code>awg4</code>) · Нет хэндшейка (>3 мин)
  ```
- **Восстановление сессии шлюза**:
  ```html
  ✅ <b>[Avari] Сессия шлюза восстановилась [РЕЗЕРВ]</b>
  Каскад: <b>Общий каскад S0</b> (#1) → <b>S4 — VDSina</b> (<code>awg4</code>) · Связь восстановлена
  ```
